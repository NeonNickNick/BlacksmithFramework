# 判定流程

从一次技能声明出发，追踪判定系统的完整执行过程。

---

## 1. 总览

```
Skill Declare  →  Compile  →  Intent  →  TurnContext (Resolutions)
                                                     ↓
                                         JudgeRuleManager (11-Stage Chain)
                                                     ↓
                                            Body.GetView() (前端快照)
```

| 阶段 | 做什么 | 核心代码 |
|---|---|---|
| 声明 | `TryDeclare` → `Declare`，产出 `SourceFile` | `ClapSkill`, `GameInstance.Declare` |
| 编译 | `SourceFile.Compile(judger)`，产出 `Intent` | `DSLforSkillLogic.SourceFile.Compile` |
| 写入 | `Intent.Execute` 将 Resolution 写入 `TurnContext` | `ClapJudger.TranslateIntentsToResolutions` |
| 阶段链 | 11 个 `JudgeStage` 按优先级依次执行 | `JudgeRuleManager.Judge` |
| 执行 | 各阶段内 Resolution 被取出并结算 | `TurnContext.ExecuteImpl`, 各 `Resolution.Execute` |
| 清理 | 组件 Update、过期规则移除、Community 更新 | `OnUpdating`, `OnEnd` |

---

## 2. 声明：从输入到 SourceFile

`GameInstance.Declare` 是每回合的入口：

```csharp
// GameInstance.cs:86
var playerContext = new DefaultSkillContext(this, skillName, Player, param, stringParam);
var enemyContext = new DefaultSkillContext(this, esn, Enemy, ep, esp);

var ps = Player.Focus.Get<Skill>();
var psfs = ps.GetPassiveSkill(playerContext);
psfs.Add(ps.Declare(skillName, playerContext));

var es = Enemy.Focus.Get<Skill>();
var esfs = es.GetPassiveSkill(enemyContext);
esfs.Add(es.Declare(esn, enemyContext));

Judger.Judge(psfs, esfs);
History.SkillHistory.Add((playerContext, enemyContext));
```

`ISkillContext` 包含 `SudoOperations`（`GameInstance`）、`SkillName`、`Self`（己方 `Community`）、`Param`、`StringParam`。`Skill.Declare` 内部先 `TryDeclare`（过 Check 函数），通过后执行技能方法。三种结果：**Illegal**（未注册）、**Rejected**（Check 失败）、**Success**。

`SourceFile` 的内部结构：

```
Community _owner                          // 施放者
List<Sentence> _sentences                 // Action<Community> + SentenceType + StructureType + CanMove
Stack<Sentence> _rhetoricCache            // 修辞缓存（WithBloodSuck/WithInterupt/WithFree）
Dictionary<..., List<Mutation>> _mutationsOnCompile  // 待注册的动态规则
```

---

## 3. 编译：SourceFile → Intent

`SourceFile.Compile(judger)` 分三步：展开修辞缓存（弹出 WithBloodSuck/WithInterupt/WithFree 插入到绑定语句之后）、注册动态规则（`_mutationsOnCompile` 写入 `DynamicJudgeRulePool` 并按 `_owner` 专门化）、合并所有 `Sentence.Structure` 为单个 `Action<Community>`（多播委托）。

```csharp
// DSLforSkillLogic.cs:66
List<Sentence> sentences = new(_sentences);
int n = _rhetoricCache.Count;
for (int i = 0; i < n; ++i)
{
    var rhetoric = _rhetoricCache.Pop();
    int index = sentences.IndexOf(rhetoric.BindSentence!) + 1;
    if (index > 0)
    {
        sentences.Insert(index, new(rhetoric.Structure, rhetoric.SentenceType, StructureType.Rhetoric));
    }
}
Action<Community> result = (a) => { };
if (judger != null)
{
    foreach (var pair in _mutationsOnCompile)
    {
        judger.JudgeRuleManager.RegistJudgeRuleDynamic(pair.Key, pair.Value);
        judger.JudgeRuleManager.AddJudgeRule(_owner, pair.Key);
    }
}
foreach (var sentence in sentences)
{
    result += sentence.Structure;
}
return new Intent() { Execute = result };
```

`Intent` 只有一个 `Execute` 委托——执行它就将技能的全部效果写入 `TurnContext`。

Judger 的编译调度：被动技能最后编译（因为可能依赖主动技能的动态规则，如 Register 后 Query）。

---

## 4. 写入：Intent → TurnContext

### 4.1 TranslateIntentsToResolutions

```csharp
// ClapJudger.cs:41
foreach (var temp in _playerIntents)
{
    temp.Execute(Player);
}
foreach (var temp in _enemyIntents)
{
    temp.Execute(Enemy);
}
```

每个 `Intent.Execute` 内部是合并后的 `Sentence.Structure` 链。以 `WriteAttack` 为例——Sentence 中构造 `AttackResolution`，设置其 `Execute` 回调（攻击结算逻辑），然后调用 `source.Focus.Get<TurnContext>().WriteResolution(resolution)`。

### 4.2 预处理钩子

```csharp
// TurnContext.cs:37
public override void WriteResolution(IResolution resolution)
{
    var pp = _preprocesses[resolution.GetType()];
    pp(resolution);
    base.WriteResolution(resolution);
}
```

`AddPreprocess<TResolution>(Action<TResolution>)` 在写入前拦截 Resolution，通过委托链（`+=`）组合，随 TurnContext 生命周期持续生效。

### 4.3 四种 Resolution

| Resolution | 写入语句 | 关键字段 |
|---|---|---|
| `AttackResolution` | `WriteAttack` | `Type`, `Power`, `DelayRounds`, 阶段钩子 (`OnHitArmorFirstTime`, `OnHitBody`, `OnEnd`) |
| `DefenseResolution` | `WriteDefense` | `Defense`, `Power`, `DelayRounds` |
| `EffectResolution` | `WriteEffect` | `Type`（触发阶段）, `TargetType`（Self/Enemy）, `Power` |
| `ResourceResolution` | `WriteResource` | `Type`（资源种类）, `Power`, `DelayRounds` |

`DelayRounds == 0` 的在本回合结算，`> 0` 的顺延至后续回合。

## 5. 阶段链：11 个 JudgeStage

### 5.1 StageRuleContainer

```csharp
// JudgeRuleManager.cs:13
private readonly Action<Community, Community> _baseRule;
private readonly List<RuleUnit> _overrideRules = new();
public readonly List<RuleUnit> _modifiersBefore = new();
public readonly List<RuleUnit> _modifiersAfter = new();
```

执行顺序：**Before Modifiers → 核心（Override 或 Base） → After Modifiers**。Override 替换 Base；Modifier 仅追加，不替换。

### 5.2 阶段一览

| 优先级 | 阶段 | 默认规则 | 说明 |
|---|---|---|---|
| 0 | `OnBegin` | 空 | 留给动态规则——状态检查、Buff 重置 |
| 8 | `OnEffectTaking_AfterResolutionWritten` | `TakeEffects(AfterResolutionWritten)` | 遍历双方 Effect 组件，执行 AfterResolutionWritten 类型的 EffectEntity |
| 16 | `OnEffectSwaping` | `SwapEffects` | 交换双方 `TargetType == Enemy && DelayRounds == 0` 的 EffectResolution——效果到达正确目标 |
| 32 | `OnAttackCanceling` | `CancelAttacks` | 双方攻击按 Type 排序后 1:1 对消，跳过真实伤害和延迟攻击。公式：`(a,b)→(max(0,a-b), max(0,b-a))` |
| 64 | `OnAttackSwaping` | `SwapAttacks` | 交换双方 `DelayRounds == 0` 的 AttackResolution——攻击"到达"对方 |
| 128 | `OnApplyingEffect` | `ApplyEffect` | 执行 EffectResolution，创建 EffectEntity 并存入目标 Effect 组件 |
| 256 | `OnEffectTaking_AfterTransport` | `TakeEffects(AfterTransport)` | 执行交换/传输后生效的效果（如禁言移除 Space/Time） |
| 512 | `OnApplyingOthers` | `ApplyOthers` | 依次：防御部署 → 攻击结算（装甲穿透 + HP 扣除） → 资源获取。最密集的阶段 |
| 1024 | `OnUpdating` | `Update` | 双方所有 Body 调用 Update()：Health/Defense/Effect/Skill |
| 2048 | `OnEffectTaking_AfterResult` | `TakeEffects(AfterResult)` | 结算完成后的效果触发 |
| 4096 | `OnEnd` | `UpdateCommunity` | `Community.Update()`——`ReplaceDelayed` 等延迟操作在此落地 |

### 5.3 攻击结算

攻击在 `OnApplyingOthers` 中由 `TurnContext.ExecuteImpl` 取出（只处理 `DelayRounds == 0` 的，执行后移除；`> 0` 的仅递减）：

```
真实伤害？
  ├─ 是 → 跳过防御，直接命中
  └─ 否 → 遍历防御列表（按优先级）：
            ├─ 首次命中 armorList → 触发 OnHitArmorFirstTime
            ├─ APList 中的防御 → Power *= APFactor（穿甲）
            ├─ defense.Work(...) → (剩余穿透, 已吸收)
            ├─ APList 中的防御 → Power /= APFactor（还原）
            └─ Power <= 0 → 触发 OnEnd，结束

触发 OnHitBody（扣 HP 前最后钩子）→ LoseHP → 触发 OnEnd
```

APList：`ThornReduction`, `CommonReduction`, `StoneShell`, `RealArmor`, `CommonArmor`。ArmorList：`StoneShell`, `RealArmor`, `CommonArmor`（只有装甲触发 `OnHitArmorFirstTime`，伤减不触发）。

### 5.4 其他 Resolution 执行

- **DefenseResolution**：`defense.Owner = source`，然后 `Defense.Add(resolution.Defense)`——同类型且 `CanMerge` 则 `Merge()`，否则追加。列表按优先级排序。
- **EffectResolution**：创建 `EffectEntity(type, duration, power)`，设置 `Execute` 回调，存入目标 `Effect` 组件。后续 `TakeEffects` 阶段按 `EffectType` 筛选执行。`RemainingTimes` 每次 -1，归零后在 `Update` 中移除。
- **ResourceResolution**：直接 `Resource.Gain(type, power)`。注意 `UseResource` 不在 Resolution 中——它是 `WriteFree(..., false)` 在 Intent 执行时直接调用 `Resource.Use`，先于 Resolution 写入。

## 6. 动态规则：插入与覆盖

### 6.1 注册链路

技能 DSL 中 `LinkJudgeRuleDynamic(ruleKey, mutations)` → 记录到 `_mutationsOnCompile`。`Compile(judger)` 时两步落地：

```csharp
// JudgeRuleManager.cs:359
public void AddJudgeRule(Community source, DynamicJudgeRuleName.CEValue name)
{
    List<Mutation> mutations = _dynamicPool.Query(source, name);
    foreach (var mutation in mutations)
    {
        StageRuleContainer.RuleUnit unit = new(mutation.RemainingRounds, mutation.DelayRounds, mutation.JudgeRule);
        if (mutation.RuleType == RuleType.Override)
        {
            _ruleContainers[mutation.Stage].AddOverride(unit);
        }
        else
        {
            _ruleContainers[mutation.Stage].AddModifier(unit, mutation.ModifierOrder);
        }
        _notDefaultRounds = Math.Max(_notDefaultRounds, (mutation.RemainingRounds + mutation.DelayRounds));
    }
}
```

### 6.2 模板专门化

池中以三参数模板存储：`Action<Community source, Community player, Community enemy>`。`Query` 时通过 `IfElseUtil` 固化 `source`（`source == player` 则正向执行，`== enemy` 则参数对调）——规则编写者只需关心"我 vs 对手"视角。

### 6.3 两条规则链

```csharp
// JudgeRuleManager.cs:340
public override void Judge(Community player, Community enemy)
{
    if (_notDefaultRounds == 0)
    {
        _defaultRule(player, enemy);
    }
    _notDefaultRounds--;
    {
        foreach (var stage in _ruleContainers)
        {
            stage.Value.Execute(player, enemy);
        }
    }
    ;
}
```

`_notDefaultRounds` 跟踪最长存活的动态规则。有动态规则时，默认链执行一次保证默认行为不丢失；之后动态链独立运行，反映所有 Mutation。`RuleUnit.TimePass()`：先减 `DelayRounds`（等待期），归零后减 `RemainingRounds`（存活期）。`Update` 移除到期的并调用 `TimePass`。

## 7. 清理与更新

| 阶段 | 行为 |
|---|---|
| `OnUpdating` | `Health.Update()`（死亡检查）、`Defense.Update()`（清理 `IsDead`）、`Effect.Update()`（清理 `RemainingTimes <= 0`）、`Skill.Update()` |
| `OnEnd` | `Community.Update()`——`ReplaceDelayed` 在此落地，将暂存的新 Body 替换为当前 Focus |

## 9. 延时机制（DelayRounds）

| 对象 | 语义 |
|---|---|
| `AttackResolution` | 0 = 本回合结算；>0 = 每回合 -1，归零后结算 |
| `DefenseResolution` | 同上 |
| `EffectResolution` | 同上（EffectEntity 创建后有独立的 `RemainingTimes`/`DelayTimes`） |
| `ResourceResolution` | 同上 |
| `RuleUnit` | 先减 `DelayRounds`（等待期），归零后减 `RemainingRounds`（存活期） |

`TurnContext.ExecuteImpl` 倒序遍历列表——执行归零的并移除，非零的仅递减——保证延迟条目不受列表变更影响。
