# 判定流程

从一次技能声明出发，追踪判定系统的完整执行过程。

---

## 1. 总览

```
Skill Declare  →  Compile  →  Intent  →  TurnContext (Resolutions)
                                                     ↓
                                         JudgeRuleManager (11-Stage Chain)
                                                     ↓
                                            Body.GetView() (前端快照)
```

| 阶段 | 做什么 | 核心代码 |
|---|---|---|
| 声明 | `TryDeclare` → `Declare`，产出 `SourceFile` | `ClapSkill`, `GameInstance.Declare` |
| 编译 | `SourceFile.Compile(judger)`，产出 `Intent` | `DSLforSkillLogic.SourceFile.Compile` |
| 写入 | `Intent.Execute` 将 Resolution 写入 `TurnContext` | `ClapJudger.TranslateIntentsToResolutions` |
| 阶段链 | 11 个 `JudgeStage` 按优先级依次执行 | `JudgeRuleManager.Judge` |
| 执行 | 各阶段内 Resolution 被取出并结算 | `TurnContext.ExecuteImpl`, 各 `Resolution.Execute` |
| 清理 | 组件 Update、过期规则移除、Community 更新 | `OnUpdating`, `OnEnd` |

---

## 2. 声明：从输入到 SourceFile

`GameInstance.Declare` 是每回合的入口：

```csharp
// GameInstance.cs:86
var playerContext = new DefaultSkillContext(this, skillName, Player, param, stringParam);
var enemyContext = new DefaultSkillContext(this, esn, Enemy, ep, esp);

var ps = Player.Focus.Get<Skill>();
var psfs = ps.GetPassiveSkill(playerContext);
psfs.Add(ps.Declare(skillName, playerContext));

var es = Enemy.Focus.Get<Skill>();
var esfs = es.GetPassiveSkill(enemyContext);
esfs.Add(es.Declare(esn, enemyContext));

Judger.Judge(psfs, esfs);
History.SkillHistory.Add((playerContext, enemyContext));
```

`ISkillContext` 包含 `SudoOperations`（`GameInstance`）、`SkillName`、`Self`（己方 `Community`）、`Param`、`StringParam`。`Skill.Declare` 内部先 `TryDeclare`（过 Check 函数），通过后执行技能方法。三种结果：**Illegal**（未注册）、**Rejected**（Check 失败）、**Success**。

`SourceFile` 的内部结构：

```
Community _owner                          // 施放者
List<Sentence> _sentences                 // Action<Community> + SentenceType + StructureType + CanMove
Stack<Sentence> _rhetoricCache            // 修辞缓存（WithBloodSuck/WithInterupt/WithFree）
List<List<Mutation>> _mutationsOnCompile  // 待注册的动态规则
```

---

## 3. 编译：SourceFile → Intent

`SourceFile.Compile(judger)` 分三步：展开修辞缓存（弹出 WithBloodSuck/WithInterupt/WithFree 插入到绑定语句之后）、注册动态 Mutation（`_mutationsOnCompile` 中的每组 Mutation 直接写入 `JudgeRuleManager` 并按 `_owner` 专门化）、合并所有 `Sentence.Structure` 为单个 `Action<Community>`（多播委托）。

```csharp
// DSLforSkillLogic.cs:66
List<Sentence> sentences = new(_sentences);
int n = _rhetoricCache.Count;
for (int i = 0; i < n; ++i)
{
    var rhetoric = _rhetoricCache.Pop();
    int index = sentences.IndexOf(rhetoric.BindSentence!) + 1;
    if (index > 0)
    {
        sentences.Insert(index, new(rhetoric.Structure, rhetoric.SentenceType, StructureType.Rhetoric));
    }
}
Action<Community> result = (a) => { };
if (judger != null)
{
    foreach (var mutations in _mutationsOnCompile)
    {
        judger.JudgeRuleManager.AddJudgeRule(_owner, mutations);
    }
}
foreach (var sentence in sentences)
{
    result += sentence.Structure;
}
return new Intent() { Execute = result };
```

`Intent` 只有一个 `Execute` 委托——执行它就将技能的全部效果写入 `TurnContext`。

Judger 的编译调度：被动技能最后编译（因为可能依赖主动技能的动态注册，如 Register 后 Query）。

---

## 4. 写入：Intent → TurnContext

### 4.1 TranslateIntentsToResolutions

```csharp
// ClapJudger.cs:41
foreach (var temp in _playerIntents)
{
    temp.Execute(Player);
}
foreach (var temp in _enemyIntents)
{
    temp.Execute(Enemy);
}
```

每个 `Intent.Execute` 内部是合并后的 `Sentence.Structure` 链。以 `WriteAttack` 为例——Sentence 中构造 `AttackResolution`，设置其 `Execute` 回调（攻击结算逻辑），然后调用 `source.Focus.Get<TurnContext>().WriteResolution(resolution)`。

### 4.2 预处理钩子

```csharp
// TurnContext.cs:37
public override void WriteResolution(IResolution resolution)
{
    var pp = _preprocesses[resolution.GetType()];
    pp.ForEach(p => 
    { 
        if (p.Clock.IsRinging) 
        {
            p.Action(resolution);
        }
    });
    base.WriteResolution(resolution);
}
```

`AddPreprocess<TResolution>(Action<TResolution>, delayRounds, remainingRounds, isInfinite)` 在写入前拦截 Resolution。每个预处理钩子携带独立的 `ClapRoundClock`，可设置延迟回合、持续回合和是否无限持续。`TurnContext.Update()`（实现 `IUpdatePerRound`）每回合推进所有预处理 Clock 并清理已到期（`IsDead`）的钩子。

### 4.3 四种 Resolution

| Resolution | 写入语句 | 关键字段 |
|---|---|---|
| `AttackResolution` | `WriteAttack` | `Type`, `Power`, `Clock`（`ClapRoundClock`）, 阶段钩子 (`OnHitArmorFirstTime`, `OnHitBody`, `OnEnd`) |
| `DefenseResolution` | `WriteDefense` | `Defense`, `Power`, `Clock`（`ClapRoundClock`） |
| `EffectResolution` | `WriteEffect` | `Type`（触发阶段）, `TargetType`（Self/Enemy）, `Power`, `Clock`（`ClapRoundClock`） |
| `ResourceResolution` | `WriteResource` | `Type`（资源种类）, `Power`, `Clock`（`ClapRoundClock`） |

`Clock.IsRinging`（`DelayRounds == 0 && RemainingRounds > 0`）的在本回合结算，否则调用 `Clock.RoundPass()` 推进并顺延。

## 5. 阶段链：11 个 JudgeStage

### 5.1 StageRuleContainer

```csharp
// JudgeRuleManager.cs:12
public class RuleUnit
{
    public ClapRoundClock Clock;
    public Action<Community, Community> Rule;
}
// ...
private readonly Action<Community, Community> _baseRule;
private readonly List<RuleUnit> _overrideRules = new();
public readonly List<RuleUnit> _modifiersBefore = new();
public readonly List<RuleUnit> _modifiersAfter = new();
```

`RuleUnit` 使用 `ClapRoundClock` 管理生命周期——`IsRinging` 判断本回合是否执行，`IsDead` 判断是否应清理，`RoundPass()` 推进回合。

执行顺序：**Before Modifiers → 核心（Override 或 Base） → After Modifiers**。Override 存在时取最后一个 `IsRinging` 的替换 Base；Modifier 仅追加，不替换。每阶段执行完毕后调用 `Update()`：移除所有 `IsDead` 规则，并对剩余规则调用 `Clock.RoundPass()`。

### 5.2 阶段一览

| 优先级 | 阶段 | 默认规则 | 说明 |
|---|---|---|---|
| 0 | `OnBegin` | 空 | 留给动态注册——状态检查、Buff 重置 |
| 8 | `OnEffectSwaping` | `SwapEffects` | 交换双方 `TargetType == Enemy && Clock.IsRinging` 的 EffectResolution——效果到达正确目标 |
| 16 | `OnApplyingEffect` | `ApplyEffect` | 执行 EffectResolution，创建 EffectEntity 并存入目标 Effect 组件 |
| 32 | `OnEffectTaking_AfterResolutionWritten` | `TakeEffects(AfterResolutionWritten)` | 遍历双方 Focus 及 SummonList 的 Effect 组件，执行 AfterResolutionWritten 类型的 EffectEntity |
| 64 | `OnAttackCanceling` | `CancelAttacks` | 双方攻击按 Type 排序后 1:1 对消，跳过真实伤害和延迟攻击。公式：`(a,b)→(max(0,a-b), max(0,b-a))` |
| 128 | `OnAttackSwaping` | `SwapAttacks` | 交换双方 `Clock.IsRinging` 的 AttackResolution——攻击"到达"对方 |
| 256 | `OnEffectTaking_AfterTransport` | `TakeEffects(AfterTransport)` | 执行交换/传输后生效的效果（如禁言移除 Space/Time），同样遍历 SummonList |
| 512 | `OnApplyingOthers` | `ApplyOthers` | 依次：防御部署 → 攻击结算（装甲穿透 + HP 扣除） → 资源获取。最密集的阶段 |
| 1024 | `OnUpdating` | `Update` | `Community.Update()`——双方 Focus 和 SummonList 的 Body 调用 Update()，清理过期组件、推进 Transform 时钟、处理召唤物死亡回调 |
| 2048 | `OnEffectTaking_AfterResult` | `TakeEffects(AfterResult)` | 结算完成后的效果触发，遍历 SummonList |
| 4096 | `OnEnd` | 空 | 留给动态注册——回合结束时的清理和重置 |

### 5.3 攻击结算

攻击在 `OnApplyingOthers` 中由 `TurnContext.ExecuteImpl` 取出（只处理 `Clock.IsRinging` 的，执行后移除；否则调用 `Clock.RoundPass()` 推进）：

```
真实伤害？
  ├─ 是 → 跳过防御，直接命中
  └─ 否 → 遍历防御列表（按优先级）：
            ├─ 首次命中 armorList → 触发 OnHitArmorFirstTime
            ├─ APList 中的防御 → Power *= APFactor（穿甲）
            ├─ defense.Work(...) → (剩余穿透, 已吸收)
            ├─ APList 中的防御 → Power /= APFactor（还原）
            └─ Power <= 0 → 触发 OnEnd，结束

触发 OnHitBody（扣 HP 前最后钩子）→ LoseHP → 触发 OnEnd
```

APList：`ThornReduction`, `CommonReduction`, `StoneShell`, `RealArmor`, `CommonArmor`。ArmorList：`StoneShell`, `RealArmor`, `CommonArmor`（只有装甲触发 `OnHitArmorFirstTime`，伤减不触发）。

### 5.4 其他 Resolution 执行

- **DefenseResolution**：`defense.Owner = source`，然后 `Defense.Add(resolution.Defense)`——同类型且 `CanMerge` 则 `Merge()`，否则追加。列表按优先级排序。
- **EffectResolution**：创建 `EffectEntity(type, power, clock)`，设置 `Execute` 回调，存入目标 `Effect` 组件。后续 `TakeEffects` 阶段按 `EffectType` 筛选执行。`Clock.RoundPass()` 每次 -1 剩余回合，`IsDead` 后在 `Update` 中移除。
- **ResourceResolution**：直接 `Resource.Gain(type, power)`。注意 `UseResource` 不在 Resolution 中——它是 `WriteFree(..., false)` 在 Intent 执行时直接调用 `Resource.Use`，先于 Resolution 写入。

## 6. 动态注册：Mutation 的插入与生命周期

### 6.1 注册链路

技能 DSL 中 `LinkJudgeRuleDynamic(mutations)` → 记录到 `_mutationsOnCompile`。`Compile(judger)` 时直接落地：

```csharp
// JudgeRuleManager.cs
public void AddJudgeRule(Community source, List<Mutation> mutations)
{
    mutations.ForEach(m =>
    {
        // 通过 source 比对将三参数模板固化为 (player, enemy) 二参数规则
        var originalRule = m.JudgeRule;
        m.JudgeRule = (player, enemy) =>
        {
            if (source == player) originalRule(player, enemy);
            else originalRule(enemy, player);
        };
    });
    foreach (var mutation in mutations)
    {
        StageRuleContainer.RuleUnit unit = new(mutation.Clock, mutation.JudgeRule);
        if (mutation.RuleType == RuleType.Override)
            _ruleContainers[mutation.Stage].AddOverride(unit);
        else
            _ruleContainers[mutation.Stage].AddModifier(unit, mutation.ModifierOrder);
    }
}
```

`Mutation.Clock` 是 `ClapRoundClock`，统一管理规则的延迟和持续回合。

### 6.2 单链执行

```csharp
// JudgeRuleManager.cs
public override void Judge(Community player, Community enemy)
{
    foreach (var stage in _ruleContainers)
    {
        stage.Value.Execute(player, enemy);
    }
}
```

已简化为单链：每个阶段的 `StageRuleContainer.Execute()` 内部依次执行 Before Modifiers（仅 `IsRinging` 的）→ 核心规则（Override 或 Base）→ After Modifiers（仅 `IsRinging` 的），执行完毕后自动 `Update()`：移除 `IsDead` 规则，并对剩余规则调用 `Clock.RoundPass()` 推进回合。

## 9. ClapRoundClock 时钟机制

所有 Resolution、预处理钩子、动态规则（RuleUnit）、EffectEntity 和 Community Transform 统一使用 `ClapRoundClock` 管理时序：

| 属性/方法 | 说明 |
|---|---|
| `DelayRounds` | 延迟回合数，>0 时 `RoundPass()` 优先递减此项 |
| `RemainingRounds` | 剩余生效回合数，DelayRounds 归零后才递减 |
| `IsRinging` | `DelayRounds == 0 && RemainingRounds > 0 && !forceKill()`——当前回合应当执行 |
| `IsDead` | `RemainingRounds <= 0 \|\| forceKill()`——已失效，应被清理 |
| `RoundPass()` | 推进一回合：有延迟则减延迟，无延迟且非无限则减剩余回合 |
| `isInfinite` | 是否无限持续（不递减 RemainingRounds） |
| `forceKill` | `Func<bool>`，返回 true 时强制标记为失效（如分身死亡时终止伤害转移规则） |

**Resolution 的 Clock**：构造时设置 `delayRounds`（默认 0）和 `remainingRounds`（默认 1）。`ExecuteImpl` 检查 `IsRinging`——是则执行并移除，否则 `RoundPass()` 延至下一回合。

**预处理钩子的 Clock**：`AddPreprocess` 可设置 `delayRounds`、`remainingRounds`、`isInfinite`。`WriteResolution` 时检查 `IsRinging` 才触发。`TurnContext.Update()`（`IUpdatePerRound`）每回合推进所有预处理 Clock，`IsDead` 的从列表移除。

**RuleUnit 的 Clock**：`StageRuleContainer.Execute()` 执行后自动 `Update()`——移除 `IsDead` 规则，对剩余规则调用 `Clock.RoundPass()`。

**EffectEntity 的 Clock**：构造时传入 `ClapRoundClock`，`Effect.Update()` 清理 `Clock.IsDead` 的实体。

**Community Transform 的 Clock**：`Community.Update()` 移除 `IsDead` 的 Transform，对剩余的执行 Action 后 `RoundPass()`。

`TurnContext.ExecuteImpl` 倒序遍历列表——执行 `IsRinging` 的并移除，否则 `RoundPass()` 推进——保证延迟条目不受列表变更影响。
