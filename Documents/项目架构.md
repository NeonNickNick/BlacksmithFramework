# 项目架构

面向维护者、调试者和 Mod 开发者。

---

## 1. 项目概览

Seven-project .NET 8 方案。`Clap/ClapInfra` 是共享基础；Blacksmith 和 Xio 是两个独立的游戏项目。

```
Clap/ClapInfra  (无项目依赖)
  ↑                    ↑
BlacksmithCore          XioCore
  ↑                    ↑
BlacksmithClient        XioClient

ModExamples  (→ BlacksmithCore，示例 Mod，不在 .sln 中)
```

每个游戏由 Client 项目启动 ASP.NET Core 本地站点，用 `wwwroot` 托管静态页面，通过 `/api/*` 端点操作同一进程里的 `GameInstance`。

| 解决方案 | 内容 |
|---|---|
| `Project.sln` | 全部项目 |
| `BlacksmithOnly.sln` | Clap + Blacksmith |
| `XioOnly.sln` | Xio only |

目录结构：

```
Project/
├── Clap/
│   ├── ClapInfra/          # 共享基础（无游戏依赖）
│   └── ClapSourceGenerators/ # Roslyn 增量源生成器
├── Blacksmith/
│   ├── BlacksmithClient/   # Web 宿主（入口）
│   ├── BlacksmithCore/     # 游戏引擎
│   └── ModExamples/        # 示例 Mod
└── Xio/
    ├── XioClient/
    └── XioCore/
```

## 2. ClapInfra 核心抽象

ClapInfra 提供泛型骨架，各游戏通过继承具体化。核心类型：

### 可扩展枚举：`ClapEnum<T, TMemberAttribute>`

C# 原生 `enum` 编译后不可追加。`ClapEnum` 通过"运行时创建成员 + 全局递增唯一 ID"解决。成员通过 `[IsXxxMember(priority)]` 特性的 `public` 无参实例方法自动注册。`Create(name, priority)` 直接覆盖同名成员——这是 Mod 修改枚举优先级的基础。启动完成后 `CloseFactory()` 关闭工厂。

Blacksmith 用 `BlacksmithEnum<T>` + `[IsBlacksmithEnumMember]`；Xio 用 `XioEnum<T>` + `[IsXioEnumMember]`。

> 如何新建枚举或扩展现有枚举：[枚举Mod](./Mod基础指南/枚举Mod.md)

### 技能包源生成器：`ClapSkillPackage`

编译时由 Roslyn 增量源生成器扫描 `private` 实例方法并配对：

- `XxxCheck(ISkillContext)` → `bool`：可用性检查
- `Xxx(ISkillContext)` → `IDSLSourceFile`：技能实现

诊断级别为 **Error**：未配对的 Check 方法或错误的返回类型会阻止编译。生成文件命名 `{Namespace}.{ClassName}.SkillRegistration.g.cs`。

`PackageType.Main` = 主职业包，构造时调用 `AddModOnInit()` 合并修改器；`PackageType.Modifier` = 修改器包。

> 如何编写职业和修改器：[职业Mod](./Mod基础指南/职业Mod.md)

### 多包技能管理：`ClapSkill`

管理多个技能包，提供统一入口：
- `AddPackage` / `AddSkill` / `RemoveSkill`：动态增减技能
- `TryDeclare` → `SkillDeclareResult`（`Success` / `Rejected` / `Illegal`）
- `Declare` → `IDSLSourceFile`
- `GetAvailableSkillNames()` / `GetPassiveSkill()`

### 实体组件：`ClapBody`

按类型键存储组件的容器。`Get<T>()` 取出组件。`Update()` 遍历 `IUpdatePerRound` 组件。

Blacksmith 的 `Body` 注入 7 个组件：`Community`、`Skill`、`Health`、`Defense`、`Resource`、`Effect`、`TurnContext`。

### 决议上下文：`ClapTurnContext`

泛型回合上下文，按类型缓存 `List<TIResolution>`，同时实现 `IUpdatePerRound` 以管理预处理钩子的生命周期。核心方法：
- `WriteResolution(resolution)`：**虚方法**，子类可重写注入预处理钩子
- `Get<TResolution>()` / `Execute<TResolution>(community)`

Blacksmith 注册四种决议：`AttackResolution`、`DefenseResolution`、`ResourceResolution`、`EffectResolution`。每个决议携带一个 `ClapRoundClock`（含 `DelayRounds` 和 `RemainingRounds`），`ExecuteImpl` 只执行 `Clock.IsRinging`（延迟到期且仍有剩余次数）的决议，否则调用 `Clock.RoundPass()` 推进。支持 `AddPreprocess<TResolution>(preprocess, delayRounds, remainingRounds, isInfinite)` 预处理钩子，每个预处理自带独立的 `ClapRoundClock` 生命周期控制。

### 判定管线骨架

判定相关类型位于 `BlacksmithCore.Infra.Judgement` 命名空间下，ClapInfra 提供泛型骨架：

- **`IClapDSLSourceFile`**：CRTP 接口，定义 `Compile(TJudger?)` → `TIntent` 契约
- **`ClapJudger`**：判定主循环骨架，编排 Compile → Execute → GetRule 流程
- **`ClapJudgeRuleManager`**：抽象基类，只定义 `Judge(player, enemy)`
- **`ClapIntent`**：包含 `Action<TCommunity> Execute` 属性的抽象包装

### 工具

- **`DllLoader`**：扫描目录下所有 `*.dll`，提供 `LoadByType<T>()` 和 `LoadStaticByAttribute()` 
- **`EnumRegistry`**：泛型枚举注册表，维护 `SupportedEnumDict` 和 `CEValueTypeDict`
- **`ClapSourceGenerators`**：Roslyn 增量源生成器，新游戏 Core 项目必须引用为 analyzer
- **`ClapRoundClock`**：统一的多回合生命周期时钟（`delayRounds` + `remainingRounds` + `isInfinite` + `forceKill`）。用于 Resolution、预处理钩子、动态注册（RuleUnit）、EffectEntity 和 Community Transform
- **`ClapSharedFlag`**：引用计数式启用/禁用开关。`Disable()`/`Enable()` 支持多层嵌套禁用，用于技能包的临时切换（如 ElementalArmor 模式）
- **`ClapStateVar<T>`**：跨回合状态包装器（`.Value` / `.Set()` / `.Reset()`），用于 Buff、纹章等需要跨回合记忆的状态

## 3. 启动流程

入口：`Program.cs`。

```
ModLoader.Initialize(BaseDirectory)
  1. 读取 .blacksmith/mod.json（或 .Xio/mod.json）解析 Mod 目录
  2. DllLoader 扫描目录下 *.dll
  3. 加载 BlacksmithEnum/XioEnum 子类和 IsXxxEnumModifier 静态类 → 注册枚举 → CloseFactory()
  4. 扫描 SkillPackageBase 子类 → 注册主职业名 → 注册修改器
  5. AddModOnInit 将修改器技能复制到目标包
→ LocalHost.Start(strategies)
  配置 ASP.NET Core，绑定 http://localhost:5000，映射 API，打开浏览器
```

Mod 配置格式：`{ "key": "path" }` 或 `{ "key": ["path1", "path2"] }`。路径相对 `BaseDirectory`。

## 4. 运行时核心对象

### GameInstance

一局游戏的根容器，实现 `ISudoOperations`：

- `Community Player` / `Community Enemy`：双方阵营
- `Judger Judger`：回合裁判
- `GameHistory History`：历史记录
- `DeepCopy(preRounds)`：通过重放 `SkillHistory` 创建安全沙盒（排除最近 N 轮）
- `ProfessionSkillNames` / `EquipmentSkillNames`：全局技能分类集合

> `ISkillContext` 接口和 `[IsProfessionSkill]` / `[IsEquipmentSkill]` 用法见 [职业Mod](./Mod基础指南/职业Mod.md)。`ISudoOperations` 的高级用例见 [高级技能模式](./高级技能模式.md)。

### Community

`Body Focus` + `List<Body> SummonList`。支持召唤/分身等多角色机制。提供三个核心能力：

- `AddTransform(action, delayRounds, remainingRounds, isInfinite)`：注册定时行为（如分身创建），由内部 `ClapRoundClock` 驱动，每回合推进并在到期后自动移除
- `AddCallbackKilled(body, callback)`：注册召唤物死亡回调（如分身死亡时追加攻击）
- `Update()`：清理已死亡召唤物并触发回调 → 推进 Transform 时钟 → 更新 Focus 和各 Summon Body

### Body → BodyView

继承 `ClapBody`，通过 `Get<T>()` 访问 7 个组件。`GetView()` 返回 `BodyView` 供前端使用。

### 组件一览

| 组件 | 职责 |
|---|---|
| `Health` | HP / MHP，`GainHP` / `LoseHP` / `GainMHP` / `LoseMHP` |
| `Resource` | 资源系统，`Gold_` 前缀自动配对，`Check` / `Use` / `Gain` / `Query` / `QueryAll` |
| `Defense` | `List<DefenseBase>`，`Add`（同类型可合并后排序），`Update` 清理 `IsDead` |
| `Effect` | `List<EffectEntity>`（每个持有 `ClapRoundClock`），`Execute(type, body)`，`Update` 清理 `Clock.IsDead` 的过期效果 |
| `TurnContext` | 四种 Resolution 缓存，`ExecuteImpl` 通过 `ClapRoundClock` 延迟处理，`AddPreprocess<T>` 钩子（带独立 Clock 生命周期），`Update()` 清理过期预处理 |

### GameHistory

`List<(ISkillContext, ISkillContext)> SkillHistory`。`Swap()` 对调双方历史。

## 5. 技能系统

### SkillPackageBase

继承 `ClapSkillPackage<ISkillContext, IDSLSourceFile>`。编译时源生成器自动配对 `XxxCheck` / `Xxx`。技能名转为小写。

### MainProfession 与 ProfessionModifier

- `MainProfession`：`PackageType.Main`，构造时调用 `AddModOnInit()` 合并修改器
- `ProfessionModifier`：标注 `[IsProfessionModifier("目标名")]`，`PackageType.Modifier`

典型扩展：写 `MainProfession` → 写 `[IsProfessionModifier(nameof(Common))]` 修改器 → 在修改器中提供转职技能 → 标注 `[IsProfessionSkill]`

> 完整示例和 DSL 基础用法见 [职业Mod](./Mod基础指南/职业Mod.md)。

### [IsProfessionSkill] 与 [IsEquipmentSkill]

标记技能分类。启动时 `ProfessionRegistry.RegistProfessionEquipmentSkillName()` 扫描所有 `SkillPackageBase` 子类，将带这些特性的有效方法名（小写）注册到 `ProfessionSkillNames` / `EquipmentSkillNames`。通过 `ISudoOperations` 暴露。

- 新增职业的转职入口 → `[IsProfessionSkill]`
- 装备提供的技能 → `[IsEquipmentSkill]`。装备技能可进一步提升为独立 `MainProfession`（如 `Alchemy`、`Nightmare`），入口技能仍标 `[IsEquipmentSkill]`，通过 `AddPackage` 激活子职业，借助 `AvailableSkills` 权限系统管理子技能，避免手动硬编码技能名列表。

### ProfessionRegistry

维护 `Professions`、`ProfessionSkillNames`、`EquipmentSkillNames` 三个 `HashSet<string>`，以及 `_modifiers`（`Dictionary<string, List<Type>>`）。`AddModOnInit` 将修改器技能复制到目标包。

### PackageContainer 与 ClapSharedFlag

`Skill` 内部使用 `PackageContainer`（继承 `ClapPackageContainer<ISkillPackage>`）包装技能包，每个容器持有独立的 `ClapSharedFlag`：

- `DisableAll()`：引用计数式禁用所有包，返回被禁用的包名集合
- `Enable(HashSet<string> names)`：恢复指定包的可用状态
- `Flag.IsActive`：包是否可用（引用计数 ≤0 时可用）

这使得"进入特殊模式时禁用所有普通技能，退出时恢复"成为可能（如 ElementalArmor 模式切换）。多个调用方独立 Disable/Enable 互不干扰。

## 6. 技能 DSL

技能不直接修改战场状态，而是先翻译为 `IDSLSourceFile`（`SourceFile`）。

### SourceFile 结构

- `_owner`：`Community`
- `_sentences`：`List<Sentence>`，每条包含 `Structure`（`Action<Community>`）、`SentenceType`、`CanMove`
- `_rhetoricCache`：`Stack<Sentence>`
- `_mutationsOnCompile`：动态注册列表（`List<List<Mutation>>`）

### Pen 模式

```csharp
using Pen = Func<DSLforSkillLogic.SourceFile, DSLforSkillLogic.SourceFile>;

Pen pen = sf => sf
    .UseResource(1, ResourceType.Instance.Iron())
    .WriteAttack(3, AttackType.Instance.Physical())
    .WithBloodSuck(0.66f);

return DSL.Create(sc.Self, pen);
```

### 主要语句

| 语句 | 可移动 | 说明 |
|---|---|---|
| `WriteAttack(power, type, apFactor, delay)` | ✓ | 写入 `AttackResolution` |
| `WriteDefense(power, defense, delay)` | ✓ | 写入 `DefenseResolution`，自动设置 `defense.Owner = source` |
| `WriteResource(power, type, delay)` | ✓ | 写入 `ResourceResolution` |
| `WriteEffect(type, target, power, duration, action, delayRounds)` | ✓ | 写入 `EffectResolution`，`delayRounds` 可选（默认 0） |
| `WriteRecovery(power)` | ✓ | 直接回复 HP |
| `WriteFree(action, canMove)` | 取决于 `canMove` | 任意自定义动作 |
| `UseResource(need, type, ifCommonOnly)` | ✗ | 消耗资源（语法糖，内部 `WriteFree(..., false)`） |
| `LoseHP(loss)` / `LoseMHP(loss)` | ✗ | 扣血（语法糖，内部 `WriteFree(..., false)`） |

### WriteFree 与 Move()

`WriteFree(action, canMove)` 的 `canMove` 决定该句子在 `Move()` 所有权转移时是否保留：
- `canMove: true`（默认）→ 随 DSL 转移。用于可复用增益逻辑
- `canMove: false` → 转移时剥离。用于消耗类动作

`SourceFile.Move(newOwner)`：更换 `_owner`，剥离所有 `canMove: false` 的句子。

> DSL 语句速查和完整示例见 [职业Mod - DSL基础用法](./Mod基础指南/职业Mod.md#dsl-基础用法)。WriteFree/Move 的高级模式见 [高级技能模式](./高级技能模式.md)。

### 攻击修辞（仅 `AttackFile`）

- `WithBloodSuck(percent)`：攻击结算后按 `power * percent` 吸血
- `WithInterupt()`：首次命中护甲时移除目标 Iron/Gold_Iron/Magic 资源决议
- `WithFree(stage, action)`：在指定攻击阶段执行任意动作

### Compile(judger)

展开修辞缓存 → 注册动态 Mutation → 合并所有句子为一个 `Action<Community>` → 返回 `Intent`

## 7. 联想（Association

一个技能在运行时借用另一个职业的技能 DSL。核心流程：

1. `AssociationCheck`：通过 `sc.StringParam` 读取目标技能名 → `DeepCopy()` 创建沙盒 → `Swap()` 查看对手可用技能 → 验证目标技能
2. `Association`：在沙盒中声明目标技能得到 `SourceFile` → `stolenSF.Move(sc.Self)` 转移所有权（剥离消耗，保留攻击/防御/效果和 `canMove: true` 的自由句子） → 追加自己的消耗 → 返回合并 DSL

`canMove` 的核心意义：消耗是原主人的事，可复用逻辑随技能转移。

> 逐行拆解见 [高级技能模式 - 联想](./高级技能模式.md#7-联想-deepcopy--swap--move)。

## 8. 判定引擎

> 完整执行流程（每一步在做什么、由哪段代码驱动）见 [判定流程](./判定流程.md)。动态注册的详细机制见 [判定实现](./Mod进阶指南/判定实现.md)，写法见 [DSL与动态注册](./Mod进阶指南/DSL与动态注册.md)，实战见 [高级技能模式 - 动态注册](./高级技能模式.md#6-动态注册-linkjudgeruledynamic)。

### 完整链路

```
SkillPackage → IDSLSourceFile → Compile(Judger) → Intent
→ TurnContext (Resolutions) → JudgeRuleManager (11-Stage Chain) → Body.GetView()
```

### 11 个判定阶段

阶段按优先级升序执行，每个阶段含 base rule、override rules、before/after modifiers。优先级差值（8、16...）为 Mod 插入新阶段预留空间。

| 阶段 | 优先级 | 默认行为 |
|---|---|---|
| `OnBegin` | 0 | 空 |
| `OnEffectSwaping` | 8 | 交换双方指向敌方的即时 EffectResolution |
| `OnApplyingEffect` | 16 | 执行 EffectResolution（创建 EffectEntity） |
| `OnEffectTaking_AfterResolutionWritten` | 32 | 执行 AfterResolutionWritten 效果 |
| `OnAttackCanceling` | 64 | 按优先级 1:1 对消攻击（跳过真实伤害和延迟攻击） |
| `OnAttackSwaping` | 128 | 交换双方即时 AttackResolution |
| `OnEffectTaking_AfterTransport` | 256 | 执行 AfterTransport 效果 |
| `OnApplyingOthers` | 512 | 依次执行：防御 → 攻击 → 资源 |
| `OnUpdating` | 1024 | `Community.Update()`——清理召唤物、推进 Transform 时钟、更新所有 Body 组件 |
| `OnEffectTaking_AfterResult` | 2048 | 执行 AfterResult 效果 |
| `OnEnd` | 4096 | 空——留给动态注册 |

### 动态注册核心类型

| 类型 | 职责 |
|---|---|
| `Mutation` | 单条规则改变（`Stage`、`RuleType`、`ModifierOrder`、`JudgeRule`、`Clock`（`ClapRoundClock`）） |
| `MutationPrototype` | `Mutation` 模板版（三参数，留待专门化） |
| `JudgeRuleManager` | 管理 11 阶段 `StageRuleContainer`，`Judge()` 简化为直接遍历所有阶段；`AddJudgeRule(source, mutations)` 按 source 专门化规则后通过 `mutation.Clock` 创建 `RuleUnit` 插入对应阶段 |

### AttackResolution 结算

1. 真实伤害 → 跳过防御直接扣 HP
2. 否则按防御优先级遍历，APList 中的防御类型伤害乘以 `APFactor`，穿透后还原
3. 扣 HP 前触发 `OnHitBody`，扣除后触发 `OnEnd`
4. 阶段钩子：`OnHitArmorFirstTime`（首次命中护甲）、`OnHitBody`（穿透所有防御后）、`OnEnd`（结算完毕）

## 9. 防御系统

所有防御继承 `DefenseBase`：`Type`（决定优先级）、`Power`、`CanMerge`、`IsDead`、`Owner`（写入 `DefenseResolution` 时自动赋值）、`Work(source, owner, attack, type)`。

| 防御类型 | 优先级 | 特性 |
|---|---|---|
| `PhysicalImmunity` | -16 | 物理免疫，单回合 |
| `MagicalImmunity` | -16 | 魔法免疫，单回合 |
| `RealReduction` | 0 | 真实伤减，单回合 |
| `ThornReduction` | 8 | 刺盾，吸收物理攻击时反弹 50% 为魔法伤害 |
| `CommonReduction` | 16 | 普通伤减，单回合 |
| `StoneShell` | 32 | 岩壳，一次性吸收物理攻击 |
| `RealArmor` | 64 | 真实装甲（已定义，暂无实现） |
| `CommonArmor` | 128 | 普通装甲，耐久型 |

> 内置防御位于 `BlacksmithCore/Specific/Defense/`，Mod 自定义防御位于各自的 `ModExamples/xxxMod/Defense/`。写法见 [高级技能模式 - 自定义防御](./高级技能模式.md#4-自定义防御-继承-defensebase)。

## 12. 典型扩展路径

1. **新增职业**：继承 `MainProfession` → 写 `[IsProfessionModifier(nameof(Common))]` 修改器 → 转职方法标 `[IsProfessionSkill]` + `AddPackage` + 清理入口（详见[职业Mod](./Mod基础指南/职业Mod.md)）

3. **新增防御**：扩展 `DefenseType` → 继承 `DefenseBase` → `WriteDefense(power, new YourDefense())`（详见[高级技能模式 - 自定义防御](./高级技能模式.md#4-自定义防御-继承-defensebase)）
4. **新增动态注册**：准备 `Mutation` → `LinkJudgeRuleDynamic`（详见[DSL与动态注册](./Mod进阶指南/DSL与动态注册.md)）
5. **实现 Association**：参考 PhantomBook Mod，`DeepCopy` + `Swap` + `Move`（详见[高级技能模式 - 联想](./高级技能模式.md#7-联想-deepcopy--swap--move)）

## 13. 排障指南

- **技能按钮不可用**：区分 `Illegal`（未注册）和 `Rejected`（Check 不通过）。检查 `GetAvailableSkillNames()` 和校验函数
- **技能未出现**：最常见——返回了 `DSL.SourceFile` 而非 `IDSLSourceFile`（源生成器报告 Error）
- **Association 失败**：检查 `DeepCopy` 确定性、`canMove` 标志、目标技能是否标注 `[IsProfessionSkill]` / `[IsEquipmentSkill]`（详见[高级技能模式 - 联想](./高级技能模式.md#7-联想-deepcopy--swap--move)中 Check 函数的安全检查逻辑）
- **Mod 未加载**：确认 `mod.json` 配置、DLL 位置、特性标注、`CloseFactory()` 前完成注册
- **结算结果不对**：按链路排查——DSL → Intent → Resolution → 阶段规则 → 动态注册干扰
