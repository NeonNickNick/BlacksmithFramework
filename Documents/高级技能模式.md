# 高级技能模式

本文档专门讲解"不是纯 DSL 链式调用"的技能写法——那些需要跨回合状态、动态注册、效果系统、自定义防御、运行时技能操控或越权操作的技巧性实现。每个模式先说明解决的问题，再逐段阅读真实代码。

> 建议先阅读 [项目架构](./项目架构.md) 了解整体管线，以及 [Mod进阶指南](./Mod进阶指南/引言.md) 中的判定实现和 DSL 与动态注册。

---

## 1. 跨回合状态：`ClapStateVar<T>`

`ClapStateVar<T>` 是一个状态包装器，提供 `.Value`（读取）、`.Set(val)`（写入）、`.Reset()`（恢复默认值），并针对特定值类型补充扩展方法。相比于使用纯字段可以更明确地表示状态变化。

### 1.1 简单 Buff：BloodSigil.BloodLust

```
嗜血：支付 2 HP，下次攻击伤害 +50%（向上取整）
```

```csharp
private ClapStateVar<float> _increase = new(1f);
private int IncreaseAttack(int origin)
{
    var res = (int)MathF.Ceiling(origin * _increase.Value);
    _increase.Reset();
    return res;
}
private IDSLSourceFile BloodLust(ISkillContext sc)
{
    Pen pen = sf => sf
        .LoseHP(2)
        .WriteFree(source =>
        {
            _increase.Set(1.5f);
        }, true);
    return DSL.Create(sc.Self, pen);
}
```

关键点：
- `_increase.Set(1.5f)` 放在 `WriteFree(..., canMove: true)` 中——这意味着如果这个技能被 [Association](#7-联想-deepcopy--swap--move) 窃取，Buff 效果会随 DSL 一起转移
- `IncreaseAttack` 在每次攻击前被调用，消费 Buff 后立即 `Reset()`
- `ClapStateVar` 的初始值是 `1f`（不影响伤害），`Set(1.5f)` 后下次攻击变为 1.5 倍

### 1.2 条件效果链：Lancer 纹章系统

战矛的四个攻击技能命中后都会设置一个纹章标记，然后调用 `Others()` 消费所有已激活标记，追加对应效果到 DSL 末尾。

```
天击：命中 → 火纹，下次攻击首段 +2
龙牙：命中 → 冰纹，下次攻击获得 +2 普通装甲
霸碎：命中 → 光纹，下次攻击获得 +2 HP
连突：命中 → 暗纹，下次攻击附带两回合的 1 真实伤害
```

状态变量定义：

```csharp
private ClapStateVar<bool> _fire = new(false);
private ClapStateVar<bool> _ice = new(false);
private Pen _icePen = sf => sf
    .WriteDefense(2, new CommonArmor());
private ClapStateVar<bool> _light = new(false);
private Pen _lightPen = sf => sf
    .WriteRecovery(2);
private ClapStateVar<bool> _dark = new(false);
private Pen _darkPen = sf => sf
    .LoseMHP(1)
    .WriteAttack(1, AttackType.Instance.Real(), delayRounds: 0)
    .WriteAttack(1, AttackType.Instance.Real(), delayRounds: 1);
```

`Others()` 方法——在技能 DSL 末尾追加所有已激活纹章的效果：

```csharp
private Pen Others(Pen pen)
{
    var res = pen;
    if (_ice.Value)
    {
        _ice.Reset();
        res += _icePen;
    }
    if (_light.Value)
    {
        _light.Reset();
        res += _lightPen;
    }
    if (_dark.Value)
    {
        _dark.Reset();
        res += _darkPen;
    }
    return res;
}
```

单个技能的完整写法（天击）：

```csharp
private IDSLSourceFile SkyStrike(ISkillContext sc)
{
    Pen pen = sf => sf
        .UseResource(1, ResourceType.Instance.Iron())
        .WriteAttack(3 + Fire(), AttackType.Instance.Physical())  // Fire() 消费火纹加值
            .WithFree(AttackStage.OnHitArmorFirstTime, (a, b, c) => _fire.Set(true))
            .WithInterupt();
    return DSL.Create(sc.Self, Others(pen));  // Others 追加已激活的其他纹章效果
}
```

关键点：
- `Fire()` 读取火纹状态——如果上一回合天击命中则返回 +2（并 Reset），否则返回 0
- `WithFree(AttackStage.OnHitArmorFirstTime, ...)` 在攻击首次命中护甲时设置火纹为 true——**注意是首次命中护甲，不是造成 HP 伤害**
- `Others(pen)` 在所有攻击/防御语句之后追加已激活的其他三个纹章效果
- 四个纹章的 `Set(true)` 写在 `Others()` 之前各自的 `WithFree` 中，所以本回合**不会**触发刚设置的纹章（它要等下次攻击）
- `Pen + Pen` 操作符将两个 Pen 的语句列表连接

### 1.3 复杂状态机：Lancer.Charge

蓄力是当前最复杂的技能。它管理三个状态变量，构成一个五状态自动机：

| 状态 | `_chargeCount` | `_chargeCost` | `_wasPassive` | 含义 |
|---|---|---|---|---|
| state1 | 0 | 4 | false | 空闲 |
| state2 | 1 | 0 | false | 蓄力一层，主动 |
| state3 | 1 | 0 | true | 蓄力一层，被动触发 |
| state4 | 2 | 0 | false | 蓄力两层，主动 |
| state5 | 2 | 0 | true | 蓄力两层，被动触发 |

状态转移路径：1 → 2 → 4 → 1（主动蓄力），每次蓄力都可能因为受到攻击而跳转到平行 true 状态。

```csharp
private ClapStateVar<int> _chargeCount = new(0);     // 蓄力层数
private ClapStateVar<int> _chargeCost = new(4);       // 当前消耗 Iron 数
private ClapStateVar<bool> _wasPassive = new(false);  // 是否被动触发
```

蓄力技能的主体（先别看动态注册部分）：

```csharp
private IDSLSourceFile Charge(ISkillContext sc)
{
    int chargeCountThis = _chargeCount.Value + 1;
    Pen pen = sf => sf
        .UseResource(_chargeCost.Value, ResourceType.Instance.Iron())
        .WriteFree(a => _chargeCount.Increment(), true)
        .WriteFree(a => _chargeCost.Set(0), true)
        .RegistCallbackOnJudge(new()
        {
            new ModifierCallback(AttackCanceling_Modifier_Before,
            JudgeStage.Instance.OnAttackCanceling(),
            ModifierOrder.Before,
            new ClapRoundClock(remainingRounds: 1)),
            new ModifierCallback((player, enemy) =>
            {
                if(_chargeCount.Value == chargeCountThis && !_wasPassive.Value)
                {
                    _chargeCount.Reset();
                    _chargeCost.Reset();
                }
                _wasPassive.Reset();
            },
            JudgeStage.Instance.OnBegin(),
            ModifierOrder.Before,
            new ClapRoundClock(delayRounds: 1, remainingRounds: 1))
        });
    return DSL.Create(sc.Self, pen);
}
```

`chargeCountThis` 是一个快照变量。为什么需要它？看下面[动态注册](#6-动态注册-linkjudgeruledynamic)中的检测逻辑就明白了。

**反击规则**（挂载在 `OnAttackCanceling` 的 `ModifierCallback`（`Before`），阶段顺序见[判定实现](./Mod进阶指南/判定实现.md)）：

```csharp
private void AttackCanceling_Modifier_Before(Community player, Community enemy)
{
    if (enemy.Focus.Get<TurnContext>().Get<AttackResolution>().Find(a => a.Clock.IsRinging) == null)
    {
        return;
    }
    _wasPassive.Set(true);
    Pen pen = sf => sf
        .WriteAttack(10 + _chargeCount.Value * 4 + Fire(), AttackType.Instance.Magical())
        .WriteFree(a => _chargeCount.Reset(), true)
        .WriteFree(a => _chargeCost.Reset(), true);
    DSL.Create(player, Others(pen)).Compile().Execute(player);

}
```

释放完反击后立刻 `Reset` 蓄力状态——此时蓄力已经"发射"了。同时设置 `_wasPassive = true`（"这个反击不是我主动选的"）。

**蓄力检测回调**（`ModifierCallback` 挂载在 `OnBegin`，`delayRounds: 1`，即下回合初执行）：

```csharp
new ModifierCallback((player, enemy) =>
{
    if(_chargeCount.Value == chargeCountThis && !_wasPassive.Value)
    {
        _chargeCount.Reset();
        _chargeCost.Reset();
    }
    _wasPassive.Reset();
},
JudgeStage.Instance.OnBegin(),
ModifierOrder.Before,
new ClapRoundClock(delayRounds: 1, remainingRounds: 1))
```

检测逻辑的推理过程：
- 如果 `_chargeCount` 仍然是上次蓄力时的值（`chargeCountThis`），说明本回合没有继续使用蓄力技能 → 蓄力中断，复位
- 但有一种例外：上回合触发了反击（`_wasPassive == true`）→ 反击已经复位了状态，下回合继续蓄力是允许的，此时 `_chargeCount == 0`，不满足 `== chargeCountThis` 条件，不会复位
- 如果 `_chargeCount` 已经变了（0→1 或 1→2），说明本回合使用了蓄力 → 保持蓄力状态
- 执行完后 `_wasPassive.Reset()`，为下回合的检测做准备

为什么蓄力检测先于反击执行？因为蓄力检测规则是 `delayRounds: 0` 时在 `OnBegin`（优先级最低）执行，而反击规则在 `OnAttackCanceling` 执行。蓄力检测规则实际挂载时 `delayRounds: 1` 意味着下回合的 `OnBegin` 才触发——而那时反击（`OnAttackCanceling`，发生在同回合的后续阶段）已经执行完毕。**两条规则在同一个回合的不同阶段先后执行，时间差保证了状态机的正确性。**

## 2. 攻击阶段钩子：`WithFree(AttackStage, ...)`

**问题：** 需要在攻击结算的特定时刻执行逻辑——首次命中护甲时、结算完毕后——而不是攻击定义时。

**解决方案：** `WriteAttack` 返回 `AttackFile`，其上提供 `WithFree(AttackStage, Action<Community, Body, AttackResolution>)`，将逻辑挂到攻击结算的特定阶段。

三个阶段：
- `OnHitArmorFirstTime`：攻击首次命中护甲（不是伤减）时触发
- `OnHitBody`：穿透所有防御后、扣除 HP 前触发
- `OnEnd`：攻击结算完毕后触发（`WithBloodSuck` 和 `WithInterupt` 内部就是这个阶段）

纹章系统中四个技能的 `Set(true)` 都挂在 `OnHitArmorFirstTime`：

```csharp
.WriteAttack(3 + Fire(), AttackType.Instance.Physical())
    .WithFree(AttackStage.OnHitArmorFirstTime, (a, b, c) => _fire.Set(true))
```

这里 `(a, b, c)` 是 `(Community source, Body owner, AttackResolution attack)`——攻击方阵营、攻击方 Body、本次攻击决议。

要点：
- `OnHitArmorFirstTime` 只在**首次命中护甲**时触发一次。如果攻击直接穿透所有防御打到 HP，不触发
- 如果攻击被伤减完全吸收、没有命中护甲，也不触发
- 三段攻击（连突）的每一段 `WriteAttack` 都独立绑定自己的 `WithFree`，所以每段命中时各自判定是否设置纹章

### 2.2 动态挂载阶段钩子：`AddStage` + `OnHitBody`

`WithFree` 在 DSL 书写时绑定阶段逻辑，但有时需要通过动态注册**事后**给已有 `AttackResolution` 追加阶段钩子。`AttackResolution.AddStage(stage, action)` 允许这样做。

CrossBow 的 MarkingBolt 在命中后通过 `ModifierCallback` 给对手所有即时攻击挂上 `OnHitBody` 双倍伤害：

```csharp
new ModifierCallback((player, enemy) =>
{
    foreach(var resolution in enemy.Focus.Get<TurnContext>().Get<AttackResolution>())
    {
        if(resolution.Clock.IsRinging)
        {
            resolution.AddStage(AttackStage.OnHitBody, (community, body, aresolution) =>
            {
                aresolution.Power *= 2;
            });
        }
    }
},
JudgeStage.Instance.OnApplyingOthers(),
ModifierOrder.Before,
new ClapRoundClock(delayRounds: 1, remainingRounds: 1)),
```

关键点：
- `AddStage` 不同于 `WithFree`——它在 Resolution 已创建后动态追加钩子，适合"本回合后续所有攻击受影响"的场景
- `OnHitBody` 在防御结算完毕后、HP 扣除前触发——修改 `Power` 会直接影响最终扣血量
- `OnHitArmorFirstTime` 在首次命中护甲时触发；若攻击穿透所有防御则不触发。`OnHitBody` 始终触发（紧邻 HP 扣除前）

## 3. 效果系统：`WriteEffect`

**问题：** 需要在特定判定阶段触发跨回合效果，而不是在技能声明时立即执行。

**解决方案：** `WriteEffect(effectType, targetType, power, duration, action)` 创建一个 `EffectEntity`，在指定阶段由 `JudgeRuleManager` 执行。

```csharp
WriteEffect(EffectType type, EffectTargetType target, float power, int remainingRounds,
    Action<Community source, Body main, EffectEntity effectEntity> action,
    int delayRounds = 0)
```

- `type`：触发阶段——`AfterResolutionWritten`(0)、`AfterTransport`(8)、`AfterResult`(16)
- `target`：`Self` 或 `Enemy`
- `power`：力度
- `remainingRounds`：持续回合数
- `action`：触发时执行的逻辑
- `delayRounds`（新增）：延迟回合数，默认 0（立即生效）

### 3.1 简单阶段性效果：Warlock.Mute

```
禁言：对手本回合的时空获取无效
```

```csharp
private IDSLSourceFile Mute(ISkillContext sc)
{
    Pen pen = sf => sf
       .WriteEffect(EffectType.Instance.AfterTransport(), EffectTargetType.Instance.Enemy(), 0, 1,
       (Community source, Body main, EffectEntity effectEntity) =>
       {
           main.Get<TurnContext>().Get<ResourceResolution>().RemoveAll(r => r.Type == ResourceType.Instance.Space() || r.Type == ResourceType.Instance.Time());
       });
    return DSL.Create(sc.Self, pen);
}
```

- 效果挂载在 `AfterTransport` 阶段——交换和传输之后
- `remainingRounds: 1`，持续一回合
- 效果触发时直接操作对手 TurnContext 中的 ResourceResolution 列表，移除 Space 和 Time

### 3.2 效果内注册预处理钩子：PhantomBook.Hallucinate

```
致幻：对手下回合所有攻击延迟 +1
```

这是一个更复杂的用法——效果内部调用 `AddPreprocess`：

```csharp
private IDSLSourceFile Hallucinate(ISkillContext sc)
{
    Pen pen = sf => sf
       .UseResource(2f, ResourceType.Instance.Dream())
       .WriteEffect(EffectType.Instance.AfterResolutionWritten(), EffectTargetType.Instance.Enemy(), 0, 1,
       (Community source, Body main, EffectEntity effectEntity) =>
       {
           var tc = main.Get<TurnContext>();
           tc.Get<AttackResolution>().ForEach(a => a.Clock.DelayRounds++);
           tc.AddPreprocess<AttackResolution>(a => a.Clock.DelayRounds++);
       });
    return DSL.Create(sc.Self, pen);
}
```

关键点：
- `AfterResolutionWritten` 阶段——在 Intent 写入 Resolution 之后立即执行
- 第一行处理**已经存在于 TurnContext 中的攻击**（对手当回合已声明的攻击）
- 第二行注册 `AddPreprocess`——这是一个钩子，**之后每一笔**写入 TurnContext 的 `AttackResolution` 都会先 `Clock.DelayRounds++`，覆盖对手后续产生的攻击（如动态注册生成的反击）。`AddPreprocess` 现在支持 `delayRounds`、`remainingRounds`、`isInfinite` 参数控制钩子自身的生命周期
- `remainingRounds: 1`，钩子持续一整个回合

## 4. 自定义防御：继承 `DefenseBase`

**问题：** 需要防御行为超出内置防御的能力范围——完全免疫某种攻击类型、防御破裂后触发回调。

**解决方案：** 继承 `DefenseBase`，重写 `Work`（穿透计算）、`Update`（回合更新）、`Merge`（同类型合并）。

### 4.1 物理免疫：PhysicalImmunity

```csharp
public class PhysicalImmunity : DefenseBase
{
    public override DefenseType.CEValue Type { get; set; } = DefenseType.Instance.PhysicalImmunity();
    public override int Power { get; set; } = 0;
    public override bool CanMerge { get; set; } = false;
    public override bool IsDead { get; set; } = false;
    public override void Merge(DefenseBase addition)
    {
        //不会执行
    }
    public override void Update()
    {
        IsDead = true;
    }
    public override (int, int) Work(Body source, Body owner, int attack, AttackType.CEValue type)
    {
        if (type == AttackType.Instance.Physical())
        {
            return (0, attack);
        }
        else
        {
            return (attack, 0);
        }
    }
}
```

`Work` 返回 `(剩余穿透的攻击力, 已被吸收的伤害)`。物理攻击返回 `(0, attack)` 意味着攻击被完全吸收；其他类型返回 `(attack, 0)` 意味着完全穿透。

注意：这个防御的 `Type` 需要在 `DefenseType` 枚举中注册（优先级会影响它在防御列表中的位置）。

### 4.2 回调式装甲：NightmareArmor

```
梦魇：支付 5 HP + 1 Dream，获得物理免疫 + 梦魇装甲。梦魇装甲被击破时，移除所有梦魇专属技能，重新添加梦魇自身
```

```csharp
public class NightmareArmor : DefenseBase
{
    public override DefenseType.CEValue Type { get; set; } = DefenseType.Instance.RealArmor();
    public override int Power { get; set; } = 0;
    public int Baseline { get; set; } = 1;
    public override bool CanMerge { get; set; } = false;
    public override bool IsDead { get; set; } = false;
    private readonly Action<Community> _callback;
    public NightmareArmor(Action<Community> callback)
    {
        _callback = callback;
    }
    public override void Merge(DefenseBase addition)
    {
        //不会执行
    }
    public override void Update()
    {
        if (Power <= 0)
        {
            IsDead = true;
            _callback(Owner!);
        }
    }

    public override (int, int) Work(Body source, Body owner, int attack, AttackType.CEValue type)
    {
        var res = ((int)MathF.Max(0, attack - Power), (int)MathF.Min(attack, Power));
        Power = (int)MathF.Max(0, Power - attack);
        return res;
    }
}
```

`Update()` 在 `OnUpdating` 阶段被调用，仅在 `Power <= 0`（装甲破裂）时触发回调 `_callback(Owner!)`，传入防御持有者，实现了装甲破裂时的技能切换：

```csharp
.WriteDefense(6f, new NightmareArmor(owner =>
{
    owner.Focus.Get<Skill>().AddSkill(nameof(PhantomBook), nameof(Nightmare));
    owner.Focus.Get<Skill>().RemovePackage(nameof(Nightmare));
}))
```

注意这里 `Nightmare` 是独立的 `MainProfession`（见 [5.3](#53-模式切换-phantomboodnightmare)），因此用 `RemovePackage` 一次性移除整个子职业包，而非逐个硬编码技能名。

这个模式的关键：**通过闭包将防御行为与技能上下文绑定**。`NightmareArmor` 不需要知道技能的存在，但能执行任意回调。

### 4.3 一次性吸收：StoneShell

炼药锅的岩壳——消耗 Earth 获得一次性物理攻击吸收：

```csharp
public class StoneShell : DefenseBase
{
    public override DefenseType.CEValue Type { get; set; } = DefenseType.Instance.StoneShell();
    public override int Power { get; set; } = 0;
    public override bool CanMerge { get; set; } = true;
    public override bool IsDead { get; set; } = false;
    public override void Merge(DefenseBase addition)
    {
        //什么都不做即可
    }
    public override void Update()
    {
        //什么都不做即可
    }
    public override (int, int) Work(Body source, Body owner, int attack, AttackType.CEValue type)
    {
        var res = (0, attack);
        IsDead = true;
        return res;
    }
}
```

这是最简单的防御模式：`Work` 中直接设置 `IsDead = true`，吸收一次攻击后自动移除。`Power = 0` 且 `Merge` 为空——同类型叠加时不合并，各自独立。

### 4.5 回调式装甲（Owner 闭包）：ElementalArmor

炼药锅的元素之甲——破甲物免、每回合衰减、破裂时通过 `Owner` 回调恢复技能：

```csharp
public class ElementalArmor : DefenseBase
{
    public override DefenseType.CEValue Type { get; set; } = DefenseType.Instance.CommonArmor();
    public override int Power { get; set; } = 0;
    public override bool CanMerge { get; set; } = true;
    public override bool IsDead { get; set; } = false;
    private Action<Community> _callback;
    public ElementalArmor(Action<Community> callback)
    {
        _callback = callback;
    }
    public override void Merge(DefenseBase addition)
    {
        //什么都不做即可
    }
    public override void Update()
    {
        Power -= 2;
        if(Power <= 0)
        {
            IsDead = true;
            _callback(Owner!);
        }
    }
    public override (int, int) Work(Body source, Body owner, int attack, AttackType.CEValue type)
    {
        (int, int) res;
        if(type == AttackType.Instance.Magical())
        {
            res = ((int)MathF.Max(0, attack - Power), (int)MathF.Min(attack, Power));
        }
        else
        {
            res = (0, attack);
        } 
        Power = (int)MathF.Max(0, Power - attack);
        return res;
    }
}
```

回调签名为 `Action<Community>`，通过 `Owner` 属性（`WriteDefense` 时自动赋值）获取防御持有者，无需在 DSL 中通过闭包捕获 `sc.Self`：

```csharp
.WriteDefense(8f, new Defense.ElementalArmor(owner =>
{
    owner.Focus.Get<Skill>().RemovePackage(nameof(ElementalArmor));
    owner.Focus.Get<Skill>().Enable(packageNames);
}))
.WriteFree(source =>
{
    packageNames = source.Focus.Get<Skill>().DisableAll();
    source.Focus.Get<Skill>().AddPackage(new(new ElementalArmor()));
}, true)
```

执行流程：
1. `WriteDefense` 部署元素之甲
2. `WriteFree` 禁用所有非 ElementalArmor 技能，保存包名列表
3. 装甲每回合 `Power -= 2`，若遇魔法攻击还会额外消耗耐久
4. 装甲破裂时回调：移除 ElementalArmor 包，重新启用之前禁用的包——切换回普通模式

`packageNames` 是技能类的字段（`HashSet<string>`），通过 `WriteFree(..., canMove: true)` 传递给执行上下文。`DefenseBase.Owner` 由框架在 `WriteDefense` 执行时自动赋值——防御不需要额外传参就能知道自己的持有者。

## 5. 运行时技能操控：`AddSkill` / `RemoveSkill`

**问题：** 需要动态改变角色的可用技能列表——解锁装备技能、购买职业后屏蔽其他职业入口、梦魇模式下的技能切换。

**解决方案：** 在 `WriteFree` 中调用 `body.Get<Skill>().AddSkill(packageName, skillName)` / `RemoveSkill(packageName, skillName)`。

### 5.1 装备解锁：Warlock.Alchemy

```
炼金术：支付 2.5 Iron，解锁炼金子职业，移除"炼金术"自身
```

`Alchemy` 已被提升为独立的 `MainProfession`（包含"点铁成金"等技能），通过 `AddPackage` 追加整个子职业包，利用 `AvailableSkills` 权限管理替代手动硬编码：

### 5.2 转职屏蔽：Common.ExcludeAllProfessions

```csharp
public static void ExcludeAllProfessions(Community source)
```

`MainProfessionSkillNames` 在启动时由 `[IsProfessionSkill]` 特性填充（通过 `ProfessionRegistry.SkillMetadataDict` 延迟初始化）。这个方法遍历所有已知的转职入口技能名，从 Common 包中逐一移除。

### 5.3 模式切换：PhantomBook.Nightmare

梦魇的子技能（DreamDive、Materialize、ClingingHaunt、Channeling）已被提升为独立的 `MainProfession` —— `Nightmare` 类。PhantomBook 的 Nightmare 技能通过 `AddPackage` 激活子职业：


### 5.4 全技能禁用+恢复：Cauldron.ElementalArmor

炼药锅的元素之甲模式更进一步——进入装甲模式时**禁用所有其他技能包**，装甲破裂时**恢复原来的技能**：

```csharp
HashSet<string> packageNames = new();
// ...
.WriteDefense(8f, new Defense.ElementalArmor(owner =>

    owner.Focus.Get<Skill>().Enable(packageNames);
```

## 6. 动态注册：`RegistCallbackOnJudge`

**问题：** 需要在判定流程的特定阶段插入、覆盖或修饰默认行为——反击、反射、延迟保护。也需要注册跨回合的状态检查和清理事件。

**解决方案：** `RegistCallbackOnJudge(callbacks)` 是向判定管线动态注册回合行为的通用入口。将 `ICallbackOnJudge` 列表记录到 `_mutationsOnCompile`，在编译时按施法者专门化后插入对应 `StageRuleContainer`。使用 `ModifierCallback`（携带 `ModifierOrder.Before`/`After`）作为修饰器，使用 `OverrideCallback` 替换默认核心规则。每个回调不仅可以是"规则"（改写判定行为），也可以是纯事件回调（状态重置、标记清理等）。

> 动态注册的基础知识：ICallbackOnJudge 体系、ClapRoundClock 生命周期 ——参见 [判定实现](./Mod进阶指南/判定实现.md)。具体写法见 [DSL与动态注册](./Mod进阶指南/DSL与动态注册.md)。

### 6.1 反射：Common.Reflect

```
反射：将本回合所有即时攻击和指向敌方的效果推迟一回合
```

这是最简单的动态注册用法——两个 `ModifierCallback`，分别挂在两个阶段：

```csharp
.RegistCallbackOnJudge(
    new()
    {
        new ModifierCallback(
            ReflectRule.EffectSwaping_Modifier_After,
            JudgeStage.Instance.OnEffectSwaping(),
            ModifierOrder.After,
            new ClapRoundClock(remainingRounds: 1)),
        new ModifierCallback(
            ReflectRule.AttackSwaping_Modifier_After,
            JudgeStage.Instance.OnAttackSwaping(),
            ModifierOrder.After,
            new ClapRoundClock(remainingRounds: 1))
    });
```

`ReflectRule.EffectSwaping_Modifier_After`：

```csharp
public static void EffectSwaping_Modifier_After(Community player, Community enemy)
{
    var playerResolutions = player.Focus.Get<TurnContext>().Get<EffectResolution>();

    var reflect = playerResolutions.Where(e => e.TargetType == EffectTargetType.Instance.Enemy() || e.Clock.IsRinging).ToList();

    playerResolutions.RemoveAll(e => reflect.Contains(e));

    reflect.ForEach(e => e.Clock.DelayRounds = 1);

    playerResolutions.AddRange(reflect);
}
```

逻辑：选出所有指向敌方或即时生效的效果，将其 `Clock.DelayRounds` 设为 1，延迟到下一回合。

为什么挂在 `OnEffectSwaping` 的 After？因为需要等默认的交换逻辑执行完毕后再拦截——如果在 Before 拦截，交换逻辑可能把效果又换回来。

`ReflectRule.AttackSwaping_Modifier_After` 同理，延迟所有 `Clock.IsRinging` 的攻击。

### 6.2 反击 + 状态机：Lancer.Charge（完整版）

这在 [1.3 节](#13-复杂状态机-lancercharge) 已经详细拆解过。这里从动态注册的角度补充：

两个 `ModifierCallback` 的协同：

- **第一条**（`OnAttackCanceling` Before Modifier）：在攻击对消前检测对手是否有即时攻击，有则立即编译执行伏龙翔天并复位蓄力状态。**必须先于默认的对消逻辑执行**（Before），因为对消后攻击可能已被移除
- **第二条**（`OnBegin` Before Modifier，`delayRounds: 1`）：下回合初检测蓄力是否需要复位。`OnBegin` 是最早的阶段（优先级 0），保证在一切其他逻辑之前执行状态检查

时间线示例（假设连续蓄力两次）：

```
第 N 回合：
  OnBegin → 蓄力检测不触发（delayRounds 尚未到期）
  ... → Charge 技能执行，_chargeCount: 0→1
  OnAttackCanceling → 反击检测：对手有攻击 → 自动伏龙翔天 → 复位 → _wasPassive=true
  ... → 回合结束
第 N+1 回合：
  OnBegin → 蓄力检测触发（delayRounds 到期）：
    _chargeCount == 0，不等于 chargeCountThis(1)，不满足复位条件
    _wasPassive 复位为 false
  ... → 玩家选择继续蓄力
  Charge 技能执行，_chargeCount: 0→1（chargeCountThis=1）
  OnAttackCanceling → 对手无攻击，不反击
  ... → 回合结束
第 N+2 回合：
  OnBegin → 蓄力检测触发：
    _chargeCount == 1，等于 chargeCountThis(1) → 没有增长！
    _wasPassive == false → 不是被动触发 → 复位！
```

## 7. 联想：`DeepCopy` + `Swap` + `Move`

**问题：** 一个职业如何在运行时"借用"另一个职业的技能，保留被借技能的伤害/效果但剥离其原始成本？

**解决方案：** PhantomBook 的 Association 模式。

> 关于 `Move()` 和 `canMove` 的基础知识，参见 [职业Mod](./Mod基础指南/职业Mod.md#writefree-与-move) 中的"WriteFree 与所有权转移"章节。

### Check 函数

```csharp
private bool AssociationCheck(ISkillContext sc)
{
    string expectedSkill = sc.StringParam;
    var swapInstance = sc.SudoOperations.DeepCopy();
    var fakeSelf = sc.SudoOperations.IsPlayer(sc.Self) ? swapInstance.Enemy : swapInstance.Player;
    var fakeSkill = fakeSelf.Focus.Get<Skill>();
    var fsc = new DefaultSkillContext(swapInstance, expectedSkill, fakeSelf, sc.Param, sc.StringParam);
    if (sc.SudoOperations.GameMetadata.EquipmentSkillNames.Contains(expectedSkill) ||
        sc.SudoOperations.GameMetadata.MainProfessionSkillNames.Contains(expectedSkill) ||
        expectedSkill == $"{nameof(Association).ToLower()}" ||
        fakeSkill.TryDeclare(fsc.SkillName, fsc) != SkillDeclareResult.Success)
    {
        return false;
    }
    return sc.Self.Focus.Get<Resource>().Check(ResourceType.Instance.Dream(), 2f);
}
```

为什么需要沙盒？因为 Association 需要检查对手视角下的技能可用性——对手的技能列表、对手的资源——而这些信息对当前玩家是不可见的。`DeepCopy()` 创建一个完整的游戏状态副本，通过 `IsPlayer` 判断手动选取对手的 `Community`（不再使用 `Swap()`），然后在这个沙盒中对"假自己"做 `TryDeclare`。

安全检查的逻辑：
1. `GameMetadata.EquipmentSkillNames.Contains` — 装备技能不能偷（那是装备自带的）
2. `GameMetadata.MainProfessionSkillNames.Contains` — 转职入口不能偷（否则可以跳过资源成本变相转职）
3. `expectedSkill == "association"` — 防止递归
4. `TryDeclare != Success` — 目标技能本身不合法（资源不足或前置条件不满足）

### 生成函数

```csharp
private IDSLSourceFile Association(ISkillContext sc)
{
    string expectedSkill = sc.StringParam;
    var swapInstance = sc.SudoOperations.DeepCopy();
    var fakeSelf = sc.SudoOperations.IsPlayer(sc.Self) ? swapInstance.Enemy : swapInstance.Player;
    var fakeSkill = fakeSelf.Focus.Get<Skill>();
    var fsc = new DefaultSkillContext(swapInstance, expectedSkill, fakeSelf, sc.Param, sc.StringParam);
    var stolenSF = fakeSkill.Declare(fsc.SkillName, fsc);
    stolenSF.Move(sc.Self);
    return ((DSL.SourceFile)stolenSF)
        .UseResource(2f, ResourceType.Instance.Dream());
}
```

`Move(sc.Self)` 是核心：
1. `_owner` 重新赋值为 `sc.Self`
2. 所有 `CanMove == false` 的句子被剥离——这些正是原技能的 `UseResource`、`LoseHP`、`LoseMHP`
3. 保留攻击、防御、效果、恢复和被标记 `canMove: true` 的 `WriteFree`

所以借来的技能带着原技能的威力但不用支付原技能的成本——关联技能自己追加成本（最后一行）。

## 8. 沙盒回滚：`DeepCopy(preRounds)`

**问题：** 需要在沙盒中查看历史状态并基于历史数据做决策（如 PhantomBook 的"梦醒时分"将状态回滚到两回合前）。

**解决方案：** `DeepCopy(preRounds: N)` 通过重放历史创建安全沙盒（排除最近 N 轮），可在沙盒中读取历史 HP、资源等状态用于当前决策。更现代的做法参见 [10. 多角色分身系统](#10-多角色分身系统addtransform--addcallbackkilled--summonlist) 中的 `AddTransform` 延迟注册模式。

```csharp
private IDSLSourceFile Awakening(ISkillContext sc)
{
    var sandBoxInstance = sc.SudoOperations.DeepCopy(preRounds: 2);
    Body copiedBody = sc.SudoOperations.IsPlayer(sc.Self) ? sandBoxInstance.Player.Focus : sandBoxInstance.Enemy.Focus;
    var resource = copiedBody.Get<Resource>();
    float m = MathF.Min(2f, resource.QueryAll(ResourceType.Instance.Dream()));
    resource.Use(ResourceType.Instance.Dream(), m);
    // 基于沙盒中的历史状态执行后续操作……
    return DSL.Create(sc.Self, _ => _);
}
```

`DeepCopy(preRounds: 2)` 重放历史时排除最近 2 轮——沙盒中的状态是两回合前的快照。`DeepCopy` 不修改原游戏状态，只用于只读查询。注意：原 `ReplaceDelayed` 方法已移除，延迟 Body 替换可使用 `AddTransform` 配合 `ClapRoundClock` 实现。

## 10. 多角色分身系统：`AddTransform` + `AddCallbackKilled` + `SummonList`

**问题：** Monk 的 GhostStep 需要创建独立的分身 Body，分身有自己的技能包、HP、防御，并能与主体交互（伤害转移、死亡触发被动攻击）。

**解决方案：** `Community` 的 `SummonList` + `AddTransform`（延迟加入）+ `AddCallbackKilled`（死亡回调）。

> 源码：`Project/Blacksmith/ModExamples/MonkMod/Monk.cs` — `GhostStep` 方法（行 39-97）

### 10.1 分身创建与技能注入

```csharp
// Monk.cs:41-56
Body clone = null!;
Pen pen = sf => sf
    .UseResource(1f, ResourceType.Instance.Jade())
    .LoseHP(1)
    .WriteFree(source =>
    {
        _cloneNum.Increment();
        clone = new Body(source, $"Clone{_cloneNum.Value}");
        clone.Get<Health>().MHP = source.Focus.Get<Health>().MHP;
        clone.Get<Health>().HP = source.Focus.Get<Health>().HP;
        clone.Get<Skill>().AddPackage(new(new Clone()));
        _clones.Add(clone);
        source.AddTransform(() =>
        {
            source.SummonList.Add(clone);
        });
    }, true)
```

关键点：
- `new Body(source, name)` 创建新 Body，`source` 是 `Community`——分身自动获得完整的组件体系（Health、Defense、Effect、TurnContext）
- `clone.Get<Skill>().AddPackage(new(new Clone()))` 给分身注入 `Clone` 职业包——分身拥有独立的技能。`Clone` 是另一个 `MainProfession` 子类（见 [14. 分身作为独立 MainProfession](#14-分身作为独立-mainprofession--passiveskill)）
- `_clones` 是 `List<Body>` 字段，用于手动追踪所有分身（因为需要按生命值排序选择目标）
- `source.AddTransform(() => source.SummonList.Add(clone))` 延迟一回合将分身加入 SummonList——**这一回合分身还不存在于战场上**，但 `clone` 变量已被闭包捕获，可供后续规则引用

### 10.2 分身死亡回调

```csharp
// Monk.cs:57-64
source.AddCallbackKilled(clone, () =>
{
    _cloneNum.Decrement();
    DSL.Create(source, sf => sf
        .WriteAttack(3f, AttackType.Instance.Physical())
        .WriteAttack(2f, AttackType.Instance.Magical()))
        .Compile().Execute(source);
});
```

`AddCallbackKilled` 在 `Community.Update()` 中检测到分身 HP ≤ 0 时触发。回调中直接编译执行 DSL 追加攻击——这是 Monk 被动（"失去分身后追加 Disillusionment"）的实现。

关键点：
- `_cloneNum.Decrement()` 维护可用分身计数（最多 2 个）
- `DSL.Create(...).Compile().Execute(source)` 在回调中即时编译执行——不走正常技能声明流程，攻击直接写入 TurnContext
- 回调在 `OnUpdating` 阶段的 `Community.Update()` 中触发——此时清理已死亡召唤物

## 11. 条件持续动态注册：`isInfinite` + `forceKill`

**问题：** GhostStep 的伤害转移规则需要"只要分身还活着就一直生效"——这不是固定回合数的规则，而是绑定到外部条件的无限持续规则。

**解决方案：** `ClapRoundClock` 的 `isInfinite: true` + `forceKill` 回调。

> 源码：`Project/Blacksmith/ModExamples/MonkMod/Monk.cs` — `GhostStep` 方法（行 66-95）

```csharp
// Monk.cs:66-95
.RegistCallbackOnJudge(
    new()
    {
        new ModifierCallback((player, enemy) =>
        {
            foreach(var resolution in player.Focus.Get<TurnContext>().Get<AttackResolution>())
            {
                if(resolution.Clock.IsRinging)
                {
                    resolution.AddStage(AttackStage.OnHitBody, (community, body, aresolution) =>
                    {
                        if (clone.Get<Health>().IsKilled)
                        {
                            return;
                        }
                        int transmit = (int)MathF.Ceiling(aresolution.Power * _transmitPercent.Value);
                        clone.Get<Health>().LoseHP(transmit);
                        aresolution.Power -= transmit;
                    });
                }
            }
        },
        JudgeStage.Instance.OnApplyingOthers(),
        ModifierOrder.Before,
        new(isInfinite: true, forceKill: () =>
        {
            return clone.Get<Health>().IsKilled;
        })),
    });
```

关键点：
- `isInfinite: true`——`RoundPass()` 不递减 `RemainingRounds`，规则永不过期
- `forceKill: () => clone.Get<Health>().IsKilled`——当分身死亡时，`IsRinging` 返回 `false`（规则不再执行），`IsDead` 返回 `true`（规则被清理）
- `AddStage(AttackStage.OnHitBody, ...)` 动态追加攻击阶段钩子——对每个 `IsRinging` 的攻击，在 `OnHitBody`（扣 HP 前）插入伤害转移逻辑
- `_transmitPercent` 默认 0.5（转移 50%），Mist 期间变为 0.9（转移 90%）
- `clone` 变量通过闭包捕获——规则绑定到**创建它的那次 GhostStep 产生的特定分身**

**与固定回合规则的对比**：

| 模式 | 生命周期控制 | 适用场景 |
|---|---|---|
| `new ClapRoundClock(remainingRounds: 3)` | 固定 3 回合后到期 | 限时 Buff/Debuff |
| `new ClapRoundClock(isInfinite: true)` | 永不到期，手动移除 | 职业特性、永久光环 |
| `new ClapRoundClock(isInfinite: true, forceKill: condition)` | 条件终止 | 分身存活期间、装甲存在期间 |
| `new ClapRoundClock(delayRounds: 1, remainingRounds: 1)` | 延迟一回合触发一次 | 下回合检测/清理 |

## 12. 动态创建 EffectEntity：攻击命中时注册下回合效果

**问题：** MazeFist 需要在"攻击命中护甲时"创建一个下回合生效的闪避效果——这不是技能声明时能确定的（是否命中护甲要到结算时才知道）。

**解决方案：** `WithFree(AttackStage.OnHitArmorFirstTime, ...)` 内动态 `new EffectEntity(...)` 并注入 `source.Focus.Get<Effect>().Add(entity)`。

> 源码：`Project/Blacksmith/ModExamples/MonkMod/Monk.cs` — `MazeFist` 方法（行 114-139）

```csharp
// Monk.cs:123-138
.WriteAttack(6f, AttackType.Instance.Physical())
    .WithFree(
        AttackStage.OnHitArmorFirstTime,
        (source, target, aresolution) =>
        {
            var entity = new EffectEntity(
                EffectType.Instance.AfterTransport(),
                0,
                new ClapRoundClock(delayRounds: 1, remainingRounds: 1));
            entity.Execute = (body) =>
            {
                body.Get<TurnContext>().Get<AttackResolution>()
                    .RemoveAll(a => a.Clock.IsRinging);
            };
            source.Focus.Get<Effect>().Add(entity);
        });
```

关键点：
- `AttackStage.OnHitArmorFirstTime`——仅当攻击首次命中护甲（非伤减）时触发。若攻击直接穿透到 HP 则不触发
- `EffectType.Instance.AfterTransport()`——效果在交换/传输后阶段触发（优先级 256）
- `new ClapRoundClock(delayRounds: 1, remainingRounds: 1)`——**下回合**才生效，持续一回合
- `entity.Execute = (body) => ...`——效果触发时直接操作 TurnContext，移除所有 `IsRinging` 的攻击，实现"闪避所有直接伤害"
- `source.Focus.Get<Effect>().Add(entity)`——效果注入到**己方**（`source.Focus`），而非目标。这是因为闪避是保护自己的效果
- `WriteFree` 中 `LoseMHP(114514)` 消费最高 HP 分身——用极大值确保一次性移除

**与前文 `WriteEffect` DSL 语句的对比**：

`WriteEffect` 在 DSL 书写时静态声明效果参数；此处 `WithFree` 内的动态创建允许效果参数依赖运行时状态（如命中判定）。两种方式最终都是创建 `EffectEntity` 存入 `Effect` 组件。

## 13. OnEnd 延迟状态复位

**问题：** Mist 技能修改了 `_transmitPercent`（50% → 90%）和 `_mist` 标志（禁止重复使用），需要在 3 回合后自动复位，且复位时机必须在回合**结算完毕后**。

**解决方案：** 挂载到 `OnEnd`（优先级 4096）+ `delayRounds: 2`（加上本回合共 3 回合后触发）。

> 源码：`Project/Blacksmith/ModExamples/MonkMod/Monk.cs` — `Mist` 方法（行 147-179）

```csharp
// Monk.cs:167-177
.RegistCallbackOnJudge(new()
{
    new ModifierCallback((player, enemy) =>
    {
        _transmitPercent.Reset();
        _mist.Reset();
    },
    JudgeStage.Instance.OnEnd(),
    ModifierOrder.Before,
    new ClapRoundClock(delayRounds: 2, remainingRounds: 1))
});
```

关键点：
- `JudgeStage.Instance.OnEnd()`——在所有结算、效果触发、组件更新**之后**执行，保证复位不影响本回合的任何逻辑
- `delayRounds: 2`——Mist 本回合立即生效（`_transmitPercent.Set(0.9f)` 和 `_mist.Set(false)` 在 `WriteFree` 中），延迟 2 回合后（即第 3 回合结束时）触发复位。加上本回合，状态实际持续 3 个完整回合
- 为什么用 `OnEnd` 而不是 `OnBegin`？如果用 `OnBegin` + `delayRounds: 3`，复位会在第 4 回合**开始**时触发——这会使第 3 回合的伤害转移仍使用 90%。`OnEnd` + `delayRounds: 2` 保证在第 3 回合结算完毕后立即复位
- `_transmitPercent` 和 `_mist` 是 `ClapStateVar<T>`——`Reset()` 恢复默认值（0.5f / true）

## 14. 分身作为独立 MainProfession + PassiveSkill

**问题：** 每个分身需要每回合自动为 Monk 施加 GoldenBellCover——分身不是被动的"伤害吸收器"，而是有自主行为的独立角色。

**解决方案：** 分身的职业包 `Clone` 继承 `MainProfession`，重写 `PassiveSkillImpl` 实现每回合自动施放。`PassiveSkill` 已改为 `sealed override`，内部调用 `PassiveSkillImpl` 后自动在返回的 `SourceFile` 上设置 `IsPassive = true`，使 Judger 能区分被动/主动技能的编译顺序。

> 源码：`Project/Blacksmith/ModExamples/MonkMod/Clone.cs`（完整文件，22 行）

```csharp
// Clone.cs:10-21
public partial class Clone : MainProfession
{
    private ClapStateVar<int> _gbcTimes = new(0);
    public override IDSLSourceFile PassiveSkillImpl(ISkillContext sc)
    {
        Pen pen = sf => sf
            .WriteFree(a => _gbcTimes.Increment(), true)
            .WriteDefense(100f - 60f * _gbcTimes.Value, new PercentageReduction(baseline: 100));
        return DSL.Create(sc.Self, pen);
    }
}
```

关键点：
- `Clone` 是独立的 `MainProfession`——不是 `ProfessionModifier`，而是完整的主职业包
- `PassiveSkillImpl` 每回合由系统通过 `PassiveSkill` → `Skill.GetPassiveSkill(sc)` 自动调用——无需玩家手动声明
- `_gbcTimes` 是 `ClapStateVar<int>`，初始 0——每次被动触发递增，防御值公式化递减：100% → 40% → -20%（易伤）
- `PercentageReduction(baseline: 100)`——百分比伤减，baseline 为 100（即百分比基准）。60% × 1 = 60% 减伤，60% × 2 = 120% 即 -20%（20% 易伤）
- Monk 本体也有独立的 `_gbcTimes` 计数器——Monk 和每个 Clone 各自的 `_gbcTimes` 独立计数，互不干扰（见 `Monk.cs:102-108`）
- `Clone` 的 `PassiveSkillImpl` 作用于 `sc.Self`（分身自身），但防御的 `Owner` 由 `WriteDefense` 自动设为目标——由于被动技能的 `sc.Self` 是分身所在 Community，`WriteDefense` 的防御会部署在分身上。而规则描述"给 Monk 施加 GoldenBellCover"，实际实现是通过分身自保间接保护 Monk——因为伤害已被转移到分身上

**Clone 如何被战场识别**：`GameInstance` 中的 `GetPassiveSkill` 遍历双方 `Community` 的所有 Body（包括 SummonList），因此 Clone 的被动技能会被框架自动收集和编译。所有被动 SourceFile 的 `IsPassive` 标记确保它们在 Judger.Compile 阶段被正确处理。

## 9. 总结：各模式的适用场景

| 场景 | 模式 | 参考 |
|---|---|---|
| 下回合增伤/Buff | `ClapStateVar<T>` + `WriteFree(..., canMove: true)` | BloodLust |
| 命中后追加效果 | `WithFree(AttackStage.OnHitArmorFirstTime)` + `ClapStateVar<bool>` | 天击/龙牙/霸碎/连突 |
| 多纹章/Pen 组合 | `Pen + Pen` 操作符 + `Others()` 方法 | Lancer 纹章系统 |
| 跨阶段状态机 | `ClapStateVar` + `RegistCallbackOnJudge` | Charge |
| 阶段性效果 | `WriteEffect(effectType, targetType, ...)` | Mute |
| 拦截后续 Resolution | 效果内 `AddPreprocess<TResolution>()` | Hallucinate |
| 自定义防御行为 | 继承 `DefenseBase`，重写 `Work`/`Update` | PhysicalImmunity, NightmareArmor |
| 一次性吸收防御 | `Work` 中直接 `IsDead = true` | StoneShell |
| 防御破裂回调 | `DefenseBase` + `Action` 闭包 | NightmareArmor, ElementalArmor |
| 防御使用 Owner 回调 | `DefenseBase.Owner` + `Action<Community>` | ElementalArmor |
| 动态追加攻击阶段钩子 | `AttackResolution.AddStage(OnHitBody, ...)` | MarkingBolt |
| 解锁/屏蔽技能 | `AddSkill` / `RemoveSkill` / `AddPackage` / `RemovePackage` | Alchemy, Nightmare, ExcludeAllProfessions |
| 全技能禁用+恢复 | `DisableAll()` / `Enable(packageNames)` | ElementalArmor |
| 反射/延迟保护 | `RegistCallbackOnJudge` + After `ModifierCallback` | Reflect |
| 自动反击 | `RegistCallbackOnJudge` + Before `ModifierCallback` + 事件内编译 DSL | Charge |
| 跨职业技能复制 | `DeepCopy` + `Swap` + `Move` | Association |
| 沙盒历史查询 | `DeepCopy(preRounds: N)` | Awakening |
| 分身/召唤物创建 | `new Body(source, name)` + `AddPackage` + `AddTransform` | GhostStep |
| 召唤物死亡回调 | `AddCallbackKilled(body, callback)` 内编译执行 DSL | GhostStep |
| 条件无限规则 | `new ClapRoundClock(isInfinite: true, forceKill: condition)` | GhostStep 伤害转移 |
| 命中时动态创建效果 | `WithFree(OnHitArmorFirstTime)` 内 `new EffectEntity` + `Effect.Add` | MazeFist |
| OnEnd 延迟复位 | `OnEnd` + `delayRounds: N` | Mist |
| 分身被动技能 | 分身 `MainProfession` 重写 `PassiveSkillImpl` | Clone |
| 动态防御值 | `WriteDefense(formula, new PercentageReduction(baseline))` | GoldenBellCover |
